## 一、背景与问题诊断

当前 POC 已覆盖需求文档全部 7 子系统的显性功能与多项隐性需求（可追溯/角色/规模/增量重解析/全局一致性等），但存在**"堆砌感"**——单页都实现了需求，拼起来不像一个产品。

根因：**信息架构 = 需求文档的子系统清单（供应商视角），不是使用者视角。** 具体三条断层：

1. **目录未贯穿**——导入按多级目录进，但解析审核/数据库/知识页没有目录轴，用户无法"先选目录再选文档"定位到具体文档。
2. **知识库与内容数据库关系不清**——二者**都是解析的产物**，却被当作独立子系统平铺；且"知识库"= RAG 向量库 + 知识图谱，此前只把图谱当全部。
3. **闭环无 handoff + 解析展示堆砌**——11 页平铺兄弟节点，解析完的块到数据库孤立、生成引用的块改了不提示；解析审核一屏堆满细节。

## 二、设计决策（三个关键 fork）

| 决策点 | 选择 | 说明 |
|--------|------|------|
| 主要使用者/主任务 | 多角色兼顾、分层 | 不锚定单一角色，全功能呈现 |
| 导航机制 | 分区分组底座 + 角色高亮 | ——（后简化为管理员全开，见第七节） |
| 闭环串联 | 轻量 handoff + 跨页联动 | 不强制向导，自由跳转 + 牵引线 |

## 三、信息架构：分区 + 页面落位

侧栏从"11 个平级页"→"工作台 + 3 个职能分区"。每区有标题给定位（解决"看不出干嘛"），页面按"给谁、高频低频"落位。

```
工作台（全景总览，置顶无分区）

▎主流程 · 活化闭环              ← 编制员/审核员日常，高频
  ├ 内容解析          （产：流水线，产物分流到下方两库）
  ├ 内容数据库        （产物仓库①：结构化元素 + 参数；目录轴贯穿）
  ├ 知识库与图谱      （产物仓库②：RAG 向量库 + 知识图谱；目录轴贯穿）
  ├ 手册生成          （消费：从两库组装新文件）
  └ AI辅助编辑        （生成/编辑子环节，唤起式）

▎治理保障                        ← 数据管理员/审核员，中频
  └ 内容治理          （术语/质量/去重/变更/全局一致性，横切两库）

▎配置与运维                      ← 管理员，低频
  ├ 数据模型          （结构定义 + 扩展字段 + 枚举字典）
  ├ 规则梳理          （前置一次性，存量分析）
  ├ 系统管理          （用户/角色/部门）
  └ 审计日志          （留痕追溯）
```

### 关键边界修复

- **内容数据库 vs 数据模型 职责分开**（此前重叠）：
  - 内容数据库 = "数据本身"——高频工作台，检索/版本/diff/对比，归主流程。
  - 数据模型 = "数据怎么组织"——四层结构定义、扩展字段管理、枚举字典维护，低频、管理员向，归配置与运维。
- **规则梳理**归配置与运维并标"前置一次性"——项目启动期存量分析，非日常功能，从主流程移出，避免编制员干扰。
- **AI辅助编辑**留主流程但定位为"生成/编辑子环节"，不做独立大入口。

### 与需求文档的对应

3 个分区 = 需求里「解析-入库-治理-生成主链 + 治理 + 配置运维」三类，按使用频次/角色重组而非硬抄子系统清单。需求每个子系统功能点不丢，只换归属。

## 四、目录轴贯穿

把"多级目录"（项目 → 区域 → 设备 → 厂家 → 文档）做成**所有文档相关页共享的导航轴**：

- 目录由导入页建立，**抽取为共享目录元数据（`NP.store.docTree`）**，全系统复用同一份（当前 parse 页内联的 docTree 提升为全局共享）。
- **解析审核页**顶部加目录选择器（项目→设备→文档），选定文档后下方才是 章节树/原文/AI提取 三栏——解决"审核页怎么定位文档"。
- **内容数据库**左侧目录树作为检索维度之一（已有，保留）。
- **知识库与图谱**支持按文档/设备范围过滤图谱与语义检索。
- 切目录→所有页同步过滤到该范围。

## 五、解析产物流水线

解析不是单步，是多产物线分流。在解析页正面体现：

```
导入 docx/pdf
  ├ 程序结构化解析 → 章节树 / 段落 / 表格 / 图片元素 + DMC 挂接
  ├ OCR（扫描件）→ 文字版
  └ 三条产物线（并行）：
     ① 大模型参数提取 + DMC 编码  ─→ 参数表     ─→ 内容数据库
     ② 分片向量化                ─→ RAG 向量库  ─→ 知识库（语义检索）
     ③ 实体抽取/消歧/关系抽取     ─→ 知识图谱    ─→ 知识库（推理）
```

- 内容数据库 = 产物①（结构化元素 + 参数）的运营仓库。
- 知识库与图谱 = 产物②RAG 向量库 + 产物③知识图谱（二者同属知识库）。
- 解析页"解析任务调度"tab 改为流水线视图，体现产物去向（不再只是三个引擎卡片）。

## 六、闭环串联（轻量 handoff + 跨页联动）

**全局脊柱**：保留顶部已有的「阶段追踪条」（解析→数据库→知识→生成）作为"我在闭环哪一步"的常驻指示，不重做。

**跨页上下文联动**（轻量状态徽标 + 跳转按钮，非强制流程）：

| 联动 | 触发 | 表现 |
|------|------|------|
| 解析→数据库 | 一批内容块解析审核完成 | 完成 toast + "去数据库复核这 N 块"按钮；数据库里这批块带「待复核」徽标 |
| 解析→知识库 | 实体抽取审核通过并入图谱 | 图谱页对应实体亮「新入库」标记，可一键跳回解析原文 |
| 数据库→生成 | 被手册引用的通用块被修改 | 生成页预览顶部红条提示"引用的 3 处内容已变更，建议重审" |
| 知识库→解析原文 | 语义检索/图谱节点证据链 | 证据卡「跳回原文」按钮→定位到内容块所在章节 |
| 治理→数据库/生成 | 术语替换/通用块变更 | 受影响块标「已更新」；生成页提示需同步 |
| 目录轴贯穿 | 切目录 | 解析/数据库/知识页同步过滤到该范围 |

用户可自由跳转，闭环关键节点间有"牵引线"，无强制向导。

## 七、角色处理（简化）

角色分层暂不设计，**全以管理员视角展示全部功能**：3 个分区全展开、所有页可见、按钮按已有 RBAC 禁用即可，导航不做角色高亮/淡化。

- 角色体系（管理员/审核员/编制员/浏览者）与能力矩阵（edit/export/approve/admin）保留，已在系统管理页与各页按钮 gating 实现。
- 编制厂家"仅见本厂家资料"属数据范围（数据层过滤），不在导航层处理。
- 角色驱动的导航高亮作为未来增强项，本期不做。

## 八、解析展示按需分层（兼顾细节与实用性）

- **导入 tab**：左目录树 + 右文档表 + 批量操作（已实现，保留）。
- **解析任务 tab**：改流水线视图（见第五节），每产物节点显示进度 + 产出量（参数 N 条 / 分片 N 片 / 实体 N 个）。
- **解析审核 tab**：顶部目录选择器 → 左章节树 → 中 A4 级原文 + 元素清单（默认折叠，点击展开看段落/表格/图片/警示框 + 页码位置）→ 右 AI 提取（块/参数/表三子标签按需切）→ 准确率横幅置顶。默认一屏不堆满，细节按需展开。
- **增量重解析 tab**：保留（已实现）。

## 九、明确不做（YAGNI）

- 不做强制向导主线（保留自由跳转）。
- 不做角色驱动的导航高亮/淡化（本期管理员全开）。
- 不为重构重写已稳定页面，仅调整落位、加目录轴、改流水线视图、加跨页联动徽标。
- 不动 Mock 数据生成脚本结构，新增状态/联动用组件内 reactive 实现。

## 十、实施分项（概览，细则由 writing-plans 展开）

1. 侧栏分区重构（3 分区 + 分组标题 + 页面落位调整）。
2. 目录轴贯穿：抽取共享目录元数据，解析审核页加目录选择器，数据库/知识页目录过滤联动。
3. 解析任务 tab 改流水线视图。
4. 解析审核 tab 加目录选择器 + 元素清单折叠分层。
5. 跨页联动：6 条联动徽标 + 跳转按钮（解析→库、库→生成、知识→原文、治理→库/生成、目录轴）。
6. 数据模型页落位确认（已在配置与运维，内容保持"结构/扩展/关联"管理员视角）。

## 验收

- 11 页保持零控制台报错。
- 任意文档相关页可"先选目录再选文档"定位。
- 解析任务页体现三产物线分流。
- 6 条跨页联动可演示触发与跳转。
- 管理员视角下全功能可见可用。
