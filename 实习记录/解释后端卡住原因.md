已经修好，之前卡住不是单纯“模型慢”，而是队列调度、僵死 Worker 和超时重试叠加造成的。
后端为什么会卡住
GraphRAG 的执行链路是：
创建任务 → Redis 队列 → Worker 消费 → 图谱抽取 → 节点/边向量化 → 合并入库 → ACK
问题主要有四个：
GraphRAG、RAPTOR 和普通文档解析都被投递到 common 队列，重任务会互相抢占 Worker。
一些旧 Worker 虽然进程还在，但事件循环已经不工作，形成“假在线”，消息则一直停留在 Redis Pending。
图谱合并固定 180 秒超时，但当前任务实际需要约 215 秒。超时后底层线程中的 embedding 请求无法真正取消，重试又会产生重复计算。
Redis 消息只在整个任务完成后 ACK。Worker 中途僵死时，消息无法及时被其他 Worker 接管。
