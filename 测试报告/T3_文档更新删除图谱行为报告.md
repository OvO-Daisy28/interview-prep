### 关键发现

1. **增量合并，非全量重建**：GraphRAG 日志明确显示 v1 子图已存在 ES 中，跳过 LLM 提取；只有 v2 做了 LLM 提取
   ```
   [GraphRAG] doc:71af5a52ba3411f1ae024749c9f248e4 subgraph found in store, skipping LLM extraction.
   [GraphRAG] build_subgraph doc:9212527aba3611f1ae024749c9f248e4 start (chunks=16, timeout=4800s, attempts=2)
   ```

2. **同名实体合并**：实体 "PTR COOLING PUMP" 的描述同时包含 v1 的 640 和 v2 的 650，说明 `graph_merge` 函数将同名实体的描述叠加合并，而非创建重复实体。

3. **v1 数据未清理**：更新后 v1 的 640 和 36m 仍然存在于图谱中。RAGFlow 不区分旧版本和新版本——实体描述是叠加的，不是替换的。

4. **增量耗时减少 20%**：622.78s vs 全量 ~780s，因为省去了 v1 的 LLM 提取（只做 v2 提取 + 全局 merge）。

### 代码验证

源码分析（`/ragflow/rag/graphrag/general/index.py`）确认：

- **增量检查点**（L425-430）：`load_subgraph_from_store()` 检查 ES 中是否已有该 doc_id 的子图。如果存在，直接复用，跳过 LLM 提取
- **合并逻辑**（L783-804）：`merge_subgraph()` 调用 `graph_merge(old_graph, subgraph, change)` 将新子图合并到全局图。同名实体的描述被追加（非替换）
- **merge 去重**（L541-551）：`merge_subgraph_attempt` 检查 doc_id 是否已在全局图的 source_id 中，已合并的会跳过

### 关键发现

**删除文档后图谱残留**。文档 API 的 `DELETE /documents` 不会自动清理图谱。图谱记录被标记为 `removed_kwd=Y`，但 ES 中的数据仍然保留。v1 的实体和关系仍然存在于全局图中。

### 手动清理（delete_index API）

调用 `DELETE /api/v1/datasets/<id>/index?type=graph`（wipe=true 默认）后：

| 指标 | 清理前 | 清理后 |
|------|--------|--------|
| ES 中 graph 记录数 | 1 | **0** |

`delete_index` 会清除 ES 中 `knowledge_graph_kwd` 为 `["graph", "subgraph", "entity", "relation", "community_report"]` 的所有记录，并清除 phase markers。

## 综合结论

### 对「文档更新了怎么办」的回答

| 场景 | 原生行为 | 需要二开吗 |
|------|---------|-----------|
| **新增文档** | 增量合并：只处理新文档子图，合并到全局图。~10 分钟 | 不需要 |
| **修改文档（同名覆盖）** | 会被当作新文档处理（新 doc_id），旧文档子图仍保留。同名实体描述叠加，旧数据不会自动清理 | **需要**：要么先删旧文档+清图+重建，要么接受旧数据残留 |
| **删除文档** | 图谱不自动清理。ES 记录标记 `removed_kwd=Y` 但数据残留 | **需要**：手动调 `DELETE /index?type=graph` 清图，或重跑 GraphRAG |
| **精确更新（覆盖同 doc_id）** | RAGFlow 不支持覆盖同 doc_id，上传同名文件会创建新文档 | **需要二开**：若要"覆盖"语义，需先删旧文档→清图→传新文档→重建 |

### 最佳实践建议

1. **文档更新流程**：删除旧文档 → 清理图谱（`DELETE /index?type=graph`）→ 上传新文档 → 触发 GraphRAG 重建。这是最干净的方式但耗时最长（全量重建）。
2. **增量更新（可接受旧数据残留）**：直接上传新版本文档 → 触发 GraphRAG。只处理新文档（~10 分钟），但旧版本实体保留在图中。
3. **定期清理**：如果频繁更新文档，建议定期全量重建图谱以清理累积的残留数据。

### 对项目的启示

- PM 问「文档更新了怎么办」的准确回答：**RAGFlow 原生支持增量合并（新增文档），但不支持自动覆盖和自动清理（修改/删除文档）**。需要二开的内容是：文档版本管理 + 图谱自动清理触发逻辑。
- 如果业务允许旧数据短期残留，增量方案（直接上传新版）性能最优（10 分钟 vs 全量 13+ 分钟）。
