## 术语与文档约定

- **"GCN 的原始文档"** 专指 `doc/客户/原始需求/` 下的两份甲方材料：
  1. `采购文件活化项目功能需求_新_正奇发20260617.docx`（功能需求）
  2. `附件1+技术规范书.pdf`（技术规范书，44 页；**PBS 出现 27 次**，时序 5 次）
  - 注意：`doc/客户/原始需求/项目经理沟通记录.md` 是**我们与 PM 的沟通记录**，**不是**甲方原始文档。
- **PBS**（Plant Breakdown Structure，电厂/设备分解结构）：客户领域概念，技术规范书 PDF 4.2.3/4.2.3.3 明确定义（"系统、设备、部件等 PBS 对象"），树形 系统→子系统→设备→部件→零件。非 RAGFlow 概念，需二开。
- **SNS**（《核电厂设备文件结构化标准编码体系（SNS）编码规范》）：给 **PBS 节点编码**的规范。PBS=结构，SNS=编码，互补而非同一概念。中广核具体编码细则待甲方规范校准。
- **时序知识图谱**（规范书 4.2.3.3）：按设备生命周期阶段（设计/制造/安装调试/运行）**独立构建图谱版本**，用**时序标签**串联成时序链；调用时标注时间节点。本质是"版本化图谱 + 时序标签"，非另起图谱。RAGFlow 原生不支持，属二开。

## 设计要点（详见 `doc/design/`）

- 知识组织三正交轴：**PBS 分解**（挂在哪）+ **专业维度**（哪个专业）+ **时序/阶段**（哪个时间节点）。
- 交汇点 = 信息块（`information_block`）：`pbs_code` + `knowledge_type` + `specialty` + `time_node` + 内容 + 来源 + 审核 + 版本。
- 双轨存储：**PostgreSQL** 权威树/信息块 + **RAGFlow KG**（"系统PBS"实体 + 组成/从属边）+ chunk 打 `pbs_code`/`spec` 标签；检索适配层做域限定。
