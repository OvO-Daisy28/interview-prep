并发越高，embedding 单份越慢、长尾越严重：并发1 avg 11s → 并发6 avg 30s（2.7x 慢）；并发1 max 47s → 并发6 max 118s（2.5x 慢）。这是共享 CPU embedding 服务的本质——并发请求争抢推理资源，单份变慢抵消并发收益。提速正解是 GPU/独立部署，不是加并发。

131 是 34 容器混跑的共享机，embedding 服务（bge-base）在 CPU 上推理，无 GPU。长尾根因是 embedding 服务负载抖动 + CPU 争抢，非编排层问题。

最优并发数：3

建议

  • 生产配置：max_concurrent=3（确认值）
  • 换环境需重标定：131 是共享机，负载波动大；换新机器或加 GPU 后需重新跑 1/3/6 阶梯压测
  • 提速正解：给 embedding 服务配 GPU 或独立部署，而非加并发（并发6 实测无收益）
