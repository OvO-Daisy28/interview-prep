# 二次开发范围分析 — 逐条对照技术规范书与 RAGFlow 原生能力

> 日期：2026-08-11
> 依据：附件1技术规范书（44页）、项目经理沟通记录、前期调研文档
> 方法：逐条对照技术规范书 4.2 节业务功能需求与 RAGFlow v0.26.1 原生能力
> 判定标准：满足 / 部分满足（需二开补全）/ 不满足（需新建）

## 一、结论速览

技术规范书定义了 **7 个子系统**，整体不是一个"RAGFlow 插件"项目，而是一个完整的**内容管理平台**，RAGFlow 只覆盖其中"知识库与知识图谱子系统"这一块。

| 子系统 | RAGFlow 覆盖度 | 判定 |
|---|---|---|
| 3.2.1 内容解析子系统 | 部分（MinerU 版面分析 + DeepDoc） | 需二开：参数提取、信息块、表格语义解析、PBS关联 |
| 3.2.2 知识库与知识图谱子系统 | **核心覆盖区** | 需二开：时序知识图谱、版本治理、语义推理路由 |
| 3.2.3 规则梳理与建模子系统 | 不覆盖 | 需新建：聚类分析、相似度分析、术语频率分析 |
| 3.2.4 内容数据库子系统 | 不覆盖 | 需新建：关系型数据模型、枚举字典、版本管理、多维度检索 |
| 3.2.5 内容治理子系统 | 不覆盖 | 需新建：术语标准化、数据质量规则引擎、变更管理 |
| 3.2.6 手册生成子系统 | 不覆盖 | 需新建：模板引擎、内容组装、参数化填充、文档输出 |
| 3.2.7 AI辅助编辑与知识增强子系统 | 部分覆盖（知识检索） | 需二开+新建：智能写作助手、上下文感知、一致性检查 |

**一句话定论**：RAGFlow 是本项目知识库与知识图谱部分的后端服务基座，但技术规范书 70% 以上的功能需求需要新建或二开。这不算"RAGFlow 上加点补丁"，而是一个以 RAGFlow 为检索/图谱引擎之一的大型企业系统开发项目。

## 二、逐条对照分析

### 2.1 内容解析功能（4.2.1 ~ 4.2.2, 4.2.5, 4.2.6, 4.2.7, 4.2.8）

| 需求条目 | RAGFlow 原生 | 判定 | 二开/新建内容 |
|---|---|---|---|
| 批量导入 Word/PDF | 有（Web/API 批量上传） | 满足 | — |
| 章节层级识别（至少四级） | 有（DeepDoc/MinerU） | 满足 | — |
| 段落/表格/图片/注意框识别 | 有版面分析 | 部分满足 | 警告/危险标识框需定制识别 |
| 扫描版 PDF OCR ≥95% | 有（集成OCR） | 满足 | 需验证中文准确率是否达标 |
| 断点续传和失败重试 | 有异步任务，但无断点续传 | 需二开 | 批量导入编排层 |
| **参数提取（准确率≥95%）** | **无** | **需新建** | 核心二开：LLM + 规则引擎，拆到单参数级别，含适用条件、PBS归属 |
| **复合参数拆分** | **无** | **需新建** | 如"额定流量640m³/h，额定扬程36m"→ 两条记录 |
| **信息块建立** | **无** | **需新建** | PBS对象 + 专业维度 + 参数/文档/关系三类信息块，含审核流程 |
| **表格语义解析** | 有版面定位，无语义解析 | 需二开 | 故障三元组、备件清单、螺栓力矩表等结构化解析 |
| **PBS对象识别与关联** | **无** | **需新建** | 系统/设备/部件层级识别，参数→PBS关联 |
| **AI辅助多模态解析** | 部分有（LLM集成） | 需二开 | 非标准章节识别、嵌入参数提取、复杂表格语义理解 |
| **AI结果人工审核界面** | **无** | **需新建** | 原文-解析结果对照视图，逐条确认/修正，差异记录 |

**定论**：内容解析子系统是最大的二开+新建区域。RAGFlow 的 DeepDoc/MinerU 只解决了"文档→chunk"这一层，而规范书要求的是"文档→结构化参数→信息块→PBS关联"的完整链路。参数提取准确率≥95% 和信息块审核流程是硬指标，必须在 LLM + 规则引擎上专门开发。

### 3.3 "需要做中才能有结论"的归纳

以下几项不是现在能拍板的，必须在开发过程中用真实数据验证：

1. **参数提取准确率 ≥95%**：取决于实际文档的表格复杂度、参数描述方式、非标准格式比例。需要拿到甲方存量文件样本后做最小验证原型。
2. **端到端延迟 ≤2秒/5秒**：当前 E2E P50=15-23秒，瓶颈在外部 LLM。本地化 LLM 部署后能否达到，取决于模型选型、并发能力、查询路由优化效果。
3. **GraphRAG 规模化稳定性**：上万份文档的图谱合并、实体消歧、社区重算是否稳定，必须阶梯压测。
4. **模板生成质量**：手册自动生成的排版合规性、内容完整性取决于模板设计精度和存量文件结构分析质量。
5. **规则梳理结论**：章节结构框架、术语标准化字典（≥500条）、表格解析规则草案，必须先分析甲方存量文件后才能输出。
6. **PBS 对象识别准确率**：系统/设备/部件层级识别需要结合核电领域知识和甲方编码体系（SNS），需拿到编码规范和样本后验证。

## 五、开发优先级与里程碑建议

基于规范书进度要求（T+1需求设计、T+3开发完成、T+4上线）：

### P0 — T+1 需求设计阶段必须完成

1. 拿到甲方存量文件样本（至少3-5类设备手册）
2. 规则梳理与建模（章节聚类、相似度、术语分析）→ 输出规则草案
3. 内容数据库数据模型设计（四层数据模型 + 枚举字典）
4. RAGFlow GraphRAG 领域 Prompt 定制方案
5. LLM 私有化部署选型方案
6. 与甲方确认 CUD4.0 / 4A / UAU / UBA 接口

### P0 — T+1 ~ T+3 开发阶段

1. 内容解析子系统（MinerU + LLM 参数提取 + 信息块 + PBS 关联）
2. 内容数据库子系统（关系型数据库 + CRUD + 版本管理）
3. RAGFlow 二开（GraphRAG Prompt + 检索适配 + 查询路由）
4. 内容治理子系统（术语字典 + 质量规则 + 变更管理）
5. 手册生成子系统（模板引擎 + 内容组装 + Word/PDF 输出）
6. AI 辅助编辑子系统（智能写作 + 上下文检索 + 一致性检查）
7. 系统管理（权限/角色/部门/日志/统计）
8. 系统集成（4A/UAU/UBA/单点登录）

### P1 — T+3 ~ T+4 测试与上线

1. 阶梯规模压测（1/10/100/1000份）
2. 端到端性能优化（LLM 本地化 + 并发 + 查询路由）
3. 以设计院某一典型系统为验收对象，完成全链路验证
4. 安全扫描、渗透测试、代码审计
